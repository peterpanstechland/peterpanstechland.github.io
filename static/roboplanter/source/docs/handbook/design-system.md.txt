# 工位搭子 · 视觉与交互规范

版本：2026-10-25。本文是面向项目网页、参赛材料和后续界面迭代的设计规范；除标明“当前已有”的内容外均是方案，不能据此宣称固件已更新。真实屏幕的当前外观与功能见 [Indicator 界面](../indicator-ui.md) 和 [养成规则](../indicator-garden.md)。

## 1. 一眼认出的产品气质

**安静的工业物件，里面住了一个有梗的小生命。** 外层用克制的排版、清晰结构和精确数据；内层用叶片、眼睛、短句和一次小庆祝制造亲近感。高级感来自节奏和细节，而不是大量玻璃卡、霓虹线、旋转模型同时出现。

视觉主张：大块炭黑、纸白信息面、酸橙色“一口鲜绿”、少量暖橙和近距离实物摄影。网页主角是拟物圆盆、大眼睛与一株倔强幼苗，实体屏仍是现有像素精灵；二者共享性格与主张，保留各自的图形语言。Indicator 当前八套主题继续按其原生截图展示，不把网页新配色冒充已刷入固件。

## 2. 设计 token

| 用途 | 建议值 | 使用规则 |
| --- | --- | --- |
| 主背景 `ink` | `#151816` | 首屏、视频片尾；深色不是所有表面都同色 |
| 次背景 `ink-soft` | `#232924` | 少量分层，不叠四层灰 |
| 纸白 `paper` | `#F4F2E9` | 长文背景、主文字、实物说明卡 |
| 正文 `text` | `#202820` | 纸白背景上的正文 |
| 次级文字 `muted` | `#657164` | 纸白背景；深色背景改用 `#B8C2B6` |
| 主强调 `lime` | `#C7F25C` | 选中态、关键步骤、少量花叶高光 |
| 暖橙 `warm` | `#EF986B` | 花盆、嘴贫短句和少量空间点缀；不单独承担错误语义 |
| 点缀 `lilac` | `#C9BAEC` | 性格、短句和游戏奖励，不能替代状态语义 |
| 信息 `sky` | `#A8D9E6` | 查询、数据路径、链接强调 |
| 待确认 `amber` | `#F4CA73` | 旧数据、进行中、需要人确认 |
| 故障 `coral` | `#F09882` | 异常信息，搭配文字和图标，不只变红 |
| 圆角 | 8 / 16 / 24 px | 控件 / 卡片 / 展示面，不全部变药丸 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48 / 72 / 96 px | 标题离自己正文更近，离上一区块更远 |

文字与重要控件上线前逐项量测对比度：正文至少 4.5:1，大字和必要非文字边界至少 3:1。这是本项目的设计检查目标；不能因为写了 token 表就声称整站已达成无障碍符合性。酸橙色按钮优先配 `ink` 深字，不直接用纸白字。图表和状态必须有文字、纹理或形状的第二编码。

建议字体栈：正文 `"Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif`，英文标题可用系统无衬线，技术标识使用系统等宽。没有授权或打包的字体不偷偷依赖远程下载；静态站在离线/弱网时仍能读。网页正文建议 16–18 px、行高 1.65–1.8、每行约 30–40 个汉字；移动端避免三列文字卡。

屏幕继续用现有原生 16/24/32/48/64 px 位图字库。新增中文短句需要重生成字库并跑覆盖检查；不直接把网页字体配置复制给 MCU。

## 3. 信息架构与页面节奏

### 参赛项目主页

1. **第一屏：产品是什么。** 一句主张、一句功能解释、实物或明确标注的渲染、体验与接入两个按钮。旁边用一行小字标明原型状态，不在第一屏堆硬件参数。
2. **第二屏：一个 20 秒故事。** 选择“赶进度 / 想歇会 / 看看盆栽”情境；角色回应一句；一条事实卡解释回应来自用户选择、游戏状态还是传感器。
3. **第三屏：一次请求怎样走完。** 用户 → YOYO Skill → BLE → 设备动作 → 同一 ID 回包。悬停或点选节点看到事实；断线可演示 `unknown`，不只播放成功线。
4. **第四屏：看得见的工位物件。** 实拍为主，按可获得素材提供 3D 旋转或图片切换；查看接口与电源，默认模型静止。
5. **第五屏：自己接一台。** 按“核对器材 → 接线 → 默认禁用刷写 → 只读测试 → 台架动作 → 手机闭环”给步骤与预计范围。预计时间必须来自实测后再填写。
6. **第六屏：证据与下一站。** 当前实现、未验证、规划并列；硬件管理、农业扩展的入口不提前标成可用功能。

全站可见导航建议为“体验 / 接入教程 / 工作原理 / 验证记录 / 复现包”。移动端主操作始终是一个明确按钮，不用滚动后自动弹出购买或关注层。

### 长教程页

每篇开头回答“完成后得到什么 / 要准备什么 / 当前停在哪一关”。正文采用一步一图、一段可复制命令、一条预期结果、一条失败分支。针脚图同时写板侧名称、GPIO 与供电等级；颜色只能辅助，不能靠红线黑线猜电源。每张截图标版本与日期，账号、密码、token 遮盖；遮盖后检查缩略图也看不到。

### 480×480 实体屏

当前五页为植物精灵、今日状态、信息、照片、番茄钟。后续视觉变化仍应保留这条用户心智：**养成在首页，设备在状态页**。要改用“给小精灵浇水”这样的名称时，必须连同字库与原生渲染验证一起实施；本文不宣称已改。

候选控件尺寸为至少 44×44 逻辑 px，关键停止控件更大；在实际电容屏上测误触与拇指可达性。页面切换与滑动离开确认页不提交动作。状态文字不能被粒子遮住，长设备名不能挤掉断线提示。

## 4. 双层交互：情绪轻，动作重

**轻交互层**包括浏览、换主题、选择主动氛围、本地小游戏、网页示意。这一层可以俏皮、可撤回、有短动画。

**设备层**包括读取、真实浇水、开灯、停止、打印。这一层用明确动词、目标、参数、时间和结果。不把“给它一点爱”当成开泵按钮，也不让点赞、摇手机、NFC 触碰自动构成硬件授权。

真实动作候选确认文案：

> 给真实花盆浇水？
>
> 设备：RoboPlanter-XXXX　时长：1 秒
>
> 这是一次水泵动作；尚未标定流量，不显示毫升。
>
> **确认浇水 1 秒**　取消

确认后锁住重复提交入口，保留停止；先显示“设备已受理，等待结果”，收到完成才显示“本次任务已完成”。不把 `completed` 扩写成“已浇足”“植物恢复健康”；打印完成只可解释为串口发送完成，除非另有纸张传感器证据。

## 5. 所有状态都要有设计

| 状态 | 主文字 | 可用操作 | 禁止的视觉暗示 |
| --- | --- | --- | --- |
| 未配置 | “尚未绑定花盆” | 看接入教程、填写已支持配置 | 在线绿点、实时数字 |
| 查询中 | “正在读取设备” | 取消/离开，不触发动作 | 无限转圈却没有错误出口 |
| 新鲜有效 | “刚刚读取 · 土壤相对湿度 48%” | 查看来源与标定；按能力操作 | 把相对指数写成土壤含水率 |
| 未标定 | “已有原始值，尚未标定” | 查看校准教程 | 给原始 ADC 加百分号 |
| 数据过期 | “这是旧读数 · 12 秒前” | 重新查询、查看连接 | 继续用绿色健康结论 |
| 功能未启用 | “水泵未启用” | 查看接入条件 | 灰按钮无解释、假装执行 |
| 受理中 | “设备已受理，等待结果” | 查同一 ID、停止 | 提前喷出成功粒子 |
| 任务完成 | “本次软件任务完成” | 查记录、结合现场确认 | 无流量计却显示已浇 30 ml |
| 被拒绝 | “没有执行：设备忙碌” | 解释原因、待空闲后由用户新建意图 | 默默排队或自动重试 |
| 结果未知 | “结果未确认，请核对现场” | 查原 ID、停止 | 换 ID 再来一次、“失败所以没浇” |
| 重启后查无记录 | “当前设备无此记录，不能判断此前结果” | 现场检查 | 把空记录当作安全重试许可 |
| 游戏保存失败 | “成长暂未保存” | 保留游玩、重试持久化 | 显示已云同步 |

“刚刚读取”示例只在真实时间戳与有效性满足时出现。网页演示状态顶端始终有“演示状态，可切换”；不做与真实设备面板无法区分的假遥测。

## 6. 动效预算与视觉惊喜

### 第一层：所有设备都能看懂

首屏先显示静态产品图和正文，脚本、3D 或纹理失败不影响教程、状态解释和导航。文字与交互由 HTML 承担，Canvas 不能成为唯一内容。键盘有焦点圈；按钮可用 Enter/Space；图有替代说明；视频有字幕与逐字稿。系统减少动态、页面后台或手动静音模式时停止非必要动画。

### 第二层：网页粒子与 shader

设计一个“呼吸叶场”：鼠标或触点经过时，少量叶形粒子偏转再回到原位；滚动到架构页，粒子聚成一条请求路径。每段动效只讲一个意思：意图聚合、请求送达、等待结果、收到回包。等待期间是缓慢脉冲，未知时路径停在断点；成功粒子只在**明确的演示完成事件**或经接入验证的真实完成事件后发出。

当前展示页采用本地托管的 Three.js 0.180.0、程序化角色和 360 个 Gaussian falloff 点精灵；DPR 上限 1.75，渲染上限约 30 fps。WebGL 不可用时显示静态角色，弱动效偏好下停止角色运动与粒子；页面隐藏时暂停渲染。完整的请求路径动画仍是未来设计。性能预算不等于目标手机实测结果，发布前还要记录具体机型。

### 第三层：子弹时间与高斯泼溅

**已实现**的是程序化 3D 圆盆、粒子定格后视角环绕、四种心情文案、3:4 海报和横版封面导出。这里没有使用训练或重建的 3D Gaussian Splatting；柔和粒子 shader 不能被宣传成实物扫描。

展示页另有 **Tripo v3.1 一体机静态外观模型**，内嵌手机仓、屏幕、小票和绿植共用一个造型。模型为约 45 MB 的带贴图 GLB，页面先展示轻量预览图，用户点击后才下载；可旋转、重置和主动开启转台，也可返回图片卸载三维视窗。模型没有经过制造尺寸、内部结构或相机活动空间验证，不代表已建成实物。模型视窗采用隔离的本地 Three.js 0.170.0，与角色演示分别运行；隐藏页面或滚出对应视口时暂停渲染。

**尚未实现**的是实物多视角采集与高斯重建。取得真实设备素材和授权后，才可进一步制作工位物件环绕，并明确采集日期与对象；它仍不等于实时数字孪生或设备状态。未来可增加静态多角度图、MP4 转台与低画质模式。人物、屏幕内容、工牌或办公空间进入扫描前先处理隐私与素材许可。

### 性能验收目标

- 无 WebGL、加载失败、JavaScript 关闭时，产品简介与接入教程仍可读。
- 在记录了型号、浏览器、网络与构建号的至少一台中档 Android 手机上验证；不只测开发机。
- 首屏关键内容出现目标 ≤2.5 秒、交互响应目标 ≤200 ms、展示动效目标稳定 ≥30 fps；均为内部测试目标，发布报告须附实际数值和条件。
- 隐藏标签页停止渲染，关闭动态后 GPU 活动明显下降；连续查看 10 分钟观察温升和电量趋势，不凭感觉写“低功耗”。
- 主下载尽量控制在可测量范围内；3D/扫描资源分包按需加载。报告实测 gzip/brotli 大小，不能用源码体积代替传输量。

## 7. 组件与素材清单

### WS2812 环境灯：已有模式与后续联动

软件已提供 `solid`（常亮）、`breath`（呼吸）、`chase`（流动）、`rainbow`（彩虹）四种模式，默认关闭，原有灯光开关命令保持兼容；亮度与灯珠数量由构建配置决定。**代码支持不等于实机灯效通过：接线、烧录、颜色、亮度和时序仍需实测。** 网页的“关 / 柔绿 / 呼吸 / 流动 / 彩虹”是独立概念预览，不是实物回显。

| 已有软件模式 | 设计意图 | 当前表现与待验收点 |
| --- | --- | --- |
| 常亮 `solid` | 稳定的桌面氛围 | 固定绿色；实测反光与可接受亮度 |
| 呼吸 `breath` | 安静地存在 | 软件按 4 秒周期平滑明暗变化；确认实际灯带无刺眼跳变 |
| 流动 `chase` | 轻量的方向感 | 沿灯珠移动；仅一颗灯珠时退化为呼吸，实际视觉取决于数量与排布 |
| 彩虹 `rainbow` | 用户主动选择的小庆祝 | 软件按 12 秒颜色周期渐变；确认实际颜色、供电与观感 |

专注柔光、完成短庆祝、断线低刺激提示是**后续事件联动设计**，当前没有 YOYO 语义、本地番茄钟或植物健康判断与灯效的自动绑定。未来若增加完成反馈，只在取得明确事件后短暂呈现并返回原模式；连接异常仍以文字解释，不把颜色当作唯一判断。

每种模式都需提供关闭方式，记住用户亮度偏好，并在工位环境检查反光、夜间刺眼和拍摄频闪。故障、停泵与动作结果仍由文字和设备回包表达。WS2812 在本项目中定位为环境灯，不提供医疗或经过光谱标定的植物补光效果。

每个页面复用 `EvidenceBadge`（实机/原生预览/网页演示/规划）、`DeviceStateCard`、`ActionConfirmation`、`ResultTimeline`、`StepWithCheck`、`CharacterAside` 六类内容模式。这里是组件职责命名建议，不代表仓库已有这些组件。

拍摄素材至少包括：桌面全景、屏幕近景、XIAO 与接口、干湿标定过程、独立供电与驱动、一次连续的动作闭环、一次断线后的界面。人物只拍获准的人；原始素材另存，不提交含账号与凭证的屏幕录像。

导出首屏横图、3:4 封面、9:16 视频、1:1 头像时保留同一角色比例与颜色。网页提供的“给模拟搭子浇水”“换心情”“子弹时间”和“导出 3:4 海报”必须在操作附近标记模拟身份；导出海报也保留“网页交互角色 / 原型项目”，避免脱离页面后被误认成实物产品照。像素角色应保持整数倍缩放、最近邻采样；不要用模糊插值把眼睛磨成噪点。项目新角色与官方品牌素材分开，未经授权不写“荣耀官方联名”。

## 8. 发布前设计检查

先请一位未参与开发的人回答五句话：“它做什么”“哪些是真实数据”“怎样真实浇水”“结果未知该怎么办”“哪个效果只在网页里”。五项均可正确指出，再检查视觉细节。

随后测试移动端单手、放大 200%、键盘、减少动态、弱网与离线；核对每个 CTA 目标存在、每张证据标签准确、每条错误信息可恢复。最后检验社媒裁切、色彩对比和字幕遮挡。视觉验收不能替代电气、协议与手机端验收。
