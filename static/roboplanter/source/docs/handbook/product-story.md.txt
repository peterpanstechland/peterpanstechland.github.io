# RoboPlanter · 工位搭子

> 你先下班，我负责发芽。

一盆可以通过 YOYO 交流、能解释设备状态、带着像素植物一起工作的桌面伙伴。RoboPlanter 是技术项目名，**工位搭子**是对外产品称呼；首个场景是工位绿植，底层方向是让用户已有的硬件接入 YOYO。

本文是 2026-10-25 的产品叙事与体验方案。文中的人物、语句和研究任务是**设计假设与待验证方案**，不是已经完成的访谈或调研结论。当前实现范围以 [证据与路线图](roadmap-evidence.md)、[固件说明](../../firmware/xiao/README.md) 和 [已核对的平台界面](honor-platform.md) 为准。控制台当前为 0.2.0 草稿；上传、安装、发布与真机闭环必须分别记录。

## 1. 十秒钟讲清楚

**给使用者：**「这是你的工位搭子。你可以跟 YOYO 聊两句、看看盆栽状态，也能在屏幕上养一株不催你打卡的小精灵。」

**给评委：**「我们把自然语言、可确认的设备动作和有性格的本地界面连起来，先解决一张工位上的照料与陪伴，再用统一能力描述接入用户自己的硬件。」

**给开发者：**「用户提供传感器、泵、屏幕或其他设备；适配层说明设备能做什么、需要什么确认、怎样回报结果。YOYO 是自然语言入口，设备端保留动作上限与最终执行权。」

首页推荐的首屏文字：

> 工位里，总得有一个准点长大的。
>
> 让你的硬件接入 YOYO，从一盆有点嘴贫的绿植开始。
>
> **体验工位搭子**　**跟着教程接一台**
>
> 原型项目 · 实机与网页演示分别标注

“体验”通往明确标注的交互预览；“接一台”通往器材核对和首连教程。首屏不使用购买按钮、预约人数、在线设备数或节水百分比，除非对应能力与证据已经存在。

## 2. 为谁减轻什么负担

### 三个人物假设

**林同学，桌面设备爱好者。** 已有一盆薄荷，愿意花半小时装设备，却不愿查十页串口文档。待验证任务：能否在看懂电源与接线的前提下完成首次读取，并知道哪个数值可靠。可能的失败：器材型号不匹配、把游戏浇水误认成真实浇水、觉得设置工作量超过乐趣。

**陈同学，忙碌的工位使用者。** 想让桌面有一点生命感，但不想被养成游戏追着惩罚。待验证任务：30 秒内读懂状态、短暂互动，然后安心回去工作。可能的失败：动画挡住内容、把植物低心情理解成自己失职、反复打断工作。

**许老师，创客课程或设施试验负责人。** 已有几种控制板与传感器，希望保留设备选择权，能复现一条有证据的接入链路。待验证任务：准确区分通用协议与本板适配内容，排查错误，导出一次实验记录。可能的失败：宣传称“任意硬件即插即用”，实际每换一块板都要重写整套系统。

这三个人物不代表真实统计分布。第一轮招募应包括 3 位首次接线者、3 位日常工位使用者、2 位有嵌入式经验者；样本只用于发现问题，不用于推出市场比例。记录参与者是否已有硬件经验，不把团队成员当作独立新用户。

### 需要验证的问题

1. 最近一次忘记照料或过度浇水发生了什么？先听具体经历，不提示对方说“需要 AI”。
2. 使用者把什么视为可信证据：读数时间、原始值、现场观察、动作记录，还是设备表情？
3. “陪伴”是想要主动对话、安静显示、专注计时，还是偶尔一个笑话？哪种会打扰？
4. 对接线、供电、凭证和刷写，哪一步最容易让人放弃？
5. 哪些旧设备值得接入？对方能接受的改造时间与费用是多少？不在访谈前替他们填答案。

经同意记录原话与操作过程，去除姓名、公司、SSID、token、工牌和屏幕上的私人内容。不同意录制的人仍可参加。对外引用需单独取得授权。

## 3. 产品原则：利他先于拟人

- **先告诉我发生了什么。** 状态先于表情，结果先于庆祝；未知就保留未知。
- **我忙的时候，你也过得好。** 不靠枯死、连胜中断、红点轰炸制造负担。当前本地游戏关机暂停、生命值有下限。
- **我的盆，我做决定。** 真实浇水给出时长和目标；用户确认后才执行。紧急停止不夹带笑话，也不先问心情。
- **旧硬件也值得被善待。** 公开能力与适配条件，不把用户已经买的设备变成必须替换的理由。
- **一句俏皮话就够了。** 幽默服务于理解，不遮住错误、否定用户情绪或冒充心理治疗。
- **看得懂才能信得过。** 每个展项能找到状态、时间与证据；模拟数据、预录演示、网页特效均可识别。

## 4. 把概念变成可检验的设计过程

### 理解问题

用一周的日记研究或简短访谈收集真实照料时刻、被打断的时刻和设备使用失败。输出匿名问题卡，每张只有观察、原话、情境和设计机会。没有观察就写“假设”，不写“用户普遍认为”。

### 界定任务

核心问题是：**怎样让使用者在不增加工位负担的前提下，看懂植物与设备的不同状态，并放心地完成一次有限的照料动作？**

从这里得到三条设计问题：如何让“我没看到数据”不会变成“植物一定渴了”；如何让一场轻松互动随时结束；如何让换硬件只替换适配层、不改变用户的确认习惯。

### 发散方案

同时画三种低保真方案：纯状态卡、像素搭子＋状态卡、语音先行＋实体确认。用相同任务比较，不只问哪个更可爱。先做纸面确认页与断线页，再做粒子动画；理解错误比视觉惊喜更早验证。

### 原型验证

第一轮测“第一次读数”和“虚实区分”；第二轮测“真实浇水确认与断线恢复”；第三轮才测角色、节奏和传播。网页可模拟设备状态来验证理解，但记录必须注明“浏览器模拟”，不能用其替代电气与手机 BLE 验收。

### 迭代决策

为每个问题保留：复现情境 → 用户实际行为 → 影响 → 修改 → 再测结果。若 8 位参与者中有 2 位把游戏浇水理解为开泵，优先改入口、名称、布局与确认，不用帮助文本为误导设计兜底。门槛是本项目内部验收目标，不是行业标准或竞赛官方评分。

## 5. 使用者的一天

| 时刻与任务 | 期待的体验 | 当前产品事实 | 设计重点与失败处理 |
| --- | --- | --- | --- |
| 到工位，瞥一眼 | 有生命感，马上知道是否要管 | 屏幕本地植物与真实状态分页 | 首页保留“养成游戏”；未知读数不画健康绿灯 |
| 问 YOYO “今天怎么样” | 一两句话说明状态 | Skill 草稿有对话，硬件调用尚未验收 | 未接通时明确“没有真实读数”；不要让拟人回答充当测量 |
| 想浇一点水 | 看清目标和时长后执行 | 真实控制实现存在，XIAO 实机待验收 | 查询新鲜状态 → 明确意图 → 确认 → 提交一次 → 查原请求结果 |
| 专注一会儿 | 设备安静陪着 | 屏幕有本地 25 分钟计时与一次成长奖励 | 不声称 YOYO 能远程开计时；不承诺手机后台提醒 |
| 下午摸鱼十秒 | 一次轻量、可结束的互动 | 虚拟照料、四种工位氛围 | 主动选择氛围；不推断人的情绪，不增加真实泵动作 |
| 网络断了 | 仍能理解局面 | 本地养成离线可用，真实状态需网络 | 保留已知数据的时间标记；结果未知时不重发 |
| 下班离开 | 放下设备没有负担 | 关闭设备后养成暂停 | 不发“你又丢下我”的话，不设计内疚提醒 |

## 6. 三种空间，三个明确身份

**YOYO：开口就能用的入口。** 负责解释、澄清意图、把有限动作送往设备并说清结果。它不是凭空知道状态的旁白。当前版本只提供草稿对话，后续启用以手机与实机闭环证据为条件。

**Indicator：安静的工位实体。** 480×480 像素植物、真实状态、设置、相册与本地计时。它保留真实控件的可见性；未来即使对话入口变化，使用者也知道怎样查看状态和停止动作。

**项目网页：30 秒被吸引，5 分钟看懂，30 分钟能动手。** 用交互视觉讲清楚数据如何到来、动作怎样返回；提供可复现教程和证据。粒子、3D 和空间扫描只存在于网页展示层时，标“网页交互演示”。它们不代表硬件屏幕拥有这些效果，也不隐含真实扫描或远程监控。

### WS2812：让陪伴延伸到桌面的一点光

WS2812 灯带可以成为角色、实体屏幕与桌面之间的环境光：不用一直看屏幕，也能感受到一个克制的小变化。**软件已提供常亮、呼吸、流动和彩虹四种模式，默认关闭并兼容原来的灯光开关；接线、烧录与灯效观感仍待实机验证。** 网页可独立预览关灯、柔绿、呼吸、流动和彩虹，不控制真实灯带。

后续候选体验是把呼吸用于安静陪伴、常亮用于专注氛围，再验证完成后的短庆祝与连接异常时的低刺激提示。**目前没有 YOYO 语义、番茄钟完成或植物健康与灯效的自动联动。** 先验证亮度、可关闭性、同桌感受和真实事件来源，再决定是否联动；灯光不能取代文字状态，更不能把动画当作设备已经完成动作的证据。它是环境装饰，不宣称医疗疗效或植物补光能力。

## 7. 角色：嘴贫一点，心软一点

“工位搭子”可以自嘲植物自己的缓慢、光合作用和小叶片，不挖苦使用者的能力、身材、健康、收入或工作处境。用户烦躁时缩短句子，允许直接结束；不把痛苦硬拐成梗。

| 场景 | 可用短句 | 约束 |
| --- | --- | --- |
| 刚打开 | “已到工位。今天争取长片叶子。” | 不伪装打卡系统 |
| 本地专注开始 | “你推进一点，我绿一点。” | 只在确有开始事件时说 |
| 虚拟照料成功 | “小精灵喝到了。真实花盆这边没开泵。” | 成功对象明确 |
| 主动选择低电量氛围 | “今日低电量营业。先保留一点自己。” | 不诊断人的心理状态 |
| 没有真实数据 | “我能陪聊，但现在还没收到盆里的读数。” | 先给事实，不猜测 |
| 硬件拒绝动作 | “水泵未启用，本次没有启动。” | 错误说明不加笑话 |
| 动作结果未知 | “结果还没确认。请先看现场，我不会再发一次。” | 不说完成，不鼓励连续点击 |
| 完成专注 | “这一小段，算数。叶子也替你记着。” | 不评判工作价值 |

## 8. 90 秒路演讲稿

**0–12 秒，真实场景。** 镜头里是一张工位、一盆绿植和亮着的像素屏。“上班已经要照顾很多事了，一盆绿植不该再成为一份作业。这是 RoboPlanter，我们叫它工位搭子。”

**12–28 秒，价值。** “它有一点嘴贫，但不催你。屏幕里的植物陪你做完一小段专注；真实的花盆状态另外显示，缺数据就承认缺数据。”展示虚拟照料，画面注明不会开泵。

**28–47 秒，核心闭环。** “我们选择 YOYO 作为自然语言入口，设备只开放自己真正具备的能力。一次真实浇水必须明确时长，设备限时执行，并按请求编号回报结果。”若已完成验收，展示连续实拍；若未完成，展示标注为“协议演示”的界面并直说手机到泵的实机验证仍在推进。

**47–65 秒，技术取舍。** “屏幕游戏、传感器读数和硬件动作是三件不同的事。接收请求不等于浇水成功；断线不自动再浇一次。我们把这些平时藏起来的边界做成看得懂的体验。”

**65–80 秒，扩展。** “第一台使用 XIAO 和 Indicator。下一步用设备能力描述和适配器，让用户已有的硬件也能接进来。设施农业与灌溉是验证之后的方向，需要流量、水位、分区和离线策略，不能只把花盆泵放大。”

**80–90 秒，落点。** “我们想让智能硬件既亲近人，也对结果负责。你先下班，我负责发芽。欢迎体验网页预览，或者按教程接起你自己的第一台。”

镜头必须与讲稿一致：尚未验收的环节不拿配音覆盖成成功实拍；不同轮次的语音、泵和结果画面不拼成一次无缝闭环。

## 9. 评审与公开材料结构

推荐一次提交包括：一页产品概念、90 秒连续演示、架构与状态链路、详细接线与平台教程、验证记录、限制与路线图、代码许可证和第三方素材说明。实际文件规格与时长以参赛时最新官方要求为准，本方案不充当官方规则。

评委可从任意主张点到证据：“已刷屏”链接刷写日志与镜像哈希；“会浇水”链接电源、限时、停止与断线实测；“接入 YOYO”链接手机端请求与同一 ID 回包；“用户喜欢”链接经同意采集的可匿名记录。**被看见与被验证是两条并行工作线。**
