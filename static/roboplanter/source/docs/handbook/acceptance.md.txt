# 安装与功能检查

按“软件检查 → 只读采集 → 单项外设 → 手机接入”的顺序检查安装结果。操作前阅读 [硬件入门](hardware-quickstart.md)，异常处理见 [故障排查](troubleshooting.md)。

## 1. 记录配置与结果

复制以下记录头到自己的本地报告。报告可以放在本地 `build/acceptance/`；原始日志和视频可能含个人或设备信息，不要自动纳入公开仓库。

```text
测试时间与时区：
测试人或本地代号：
仓库版本/commit：
本地修改说明：
XIAO/载板型号与硬件版本：
XIAO 固件版本与配置（不含秘密值）：
Indicator 固件版本：
手机型号 / MagicOS / YOYO 版本：
Skill 技术名 / 展示名 / 版本：
入口：离线单测 / 本地 HTTP / Indicator / Skill / BLE
device_id / 硬件型号：
外设启用状态与本地最大泵时长：
相关日志与图片：
检查结果：通过 / 失败 / 未执行 / 不适用
```

每一条再记录：**输入 → 前置状态 → 请求 ID → 实际通信结果 → 实物观察 → 结论**。分享记录前去掉密码、令牌和个人账号信息。

## 2. 软件检查

先验证本机，不接设备。基础命令见 [硬件上手](hardware-quickstart.md) 与各测试目录。新设备接入基础层使用：

```bash
python3 -m unittest discover -s tests -p test_device_kit.py -v
python3 -m unittest discover -s tests -p test_mcp_result_validation.py -v
python3 integrations/device-kit/device_kit.py validate integrations/device-kit/profiles/*.json
python3 integrations/device-kit/device_kit.py mock-check \
  --profile integrations/device-kit/profiles/xiao-roboplanter-v1.json \
  --fixture integrations/device-kit/fixtures/xiao-state.json
```

成功时最后一条仍应报告 `offline_fixture_only`、`hardware_verified=false`、`yoyo_bound=false`、`execution_enabled=false`。土壤未标定或数值未知时 `usable=false`，不是测试失败，也不是“植物缺水”。

现有 MCP 模拟测试另外需要其文档指定的 Python 和固定依赖：

```bash
python -m unittest discover -s tests -p test_mcp_bridge.py -v
```

这些测试使用 mock 或本机回环服务，不是设备联调。出现 Python 或 MCP 版本不符时，记录“环境阻塞”，不能把未能导入的测试记为通过。不要为了跑测试把服务启动到公网，也不使用真实设备凭据替换 mock。

检查 C++ 控制核心时，按 [核心测试说明](../../tests/core/README.md) 执行；其中的定时、队列、ID 去重与取消行为验证软件逻辑。它们不能验证接线、电流、实际液体流量或驱动板默认电平。

## 3. 只读采集检查

按 [硬件上手](hardware-quickstart.md) 完成型号、供电、备份、刷写和空载启动。最初所有可选传感器和执行器保持禁用，泵、打印机及原载板负载物理断开。通过后一次只加入一种外设。

| 编号 | 操作 | 应记录和通过的条件 |
| --- | --- | --- |
| B01 | 查看空载启动与只读状态 | 目标型号和固件正确；未启用的值为未知；泵没有启动 |
| B02 | 验证同一设备身份 | Indicator、本机 HTTP 与串口观察对应同一 XIAO；不能只凭设备名字相似 |
| B03 | 接入单个传感器 | 字段、单位、供电与原始范围合理；有通信检测的数字传感器拔除后应无效。模拟 ADC 断线可能仍在范围内，不能仅凭 `valid` 判定探头存在，须另做断线/饱和与现场比对 |
| B04 | 土壤未标定 | 保留原始 ADC 和未标定标志；不生成土壤百分比、不推断自动浇水 |
| B05 | 完成土壤标定 | 干/湿端实测记录、方向与范围正确；百分比仍只是此探头/介质的相对值 |
| B06 | 断开 XIAO 网络 | 显示失联或不可用；屏幕游戏仍可运行但不能伪装新传感器数据 |
| B07 | 恢复网络 | 重新读取当前状态；没有自动重放此前提出的动作 |

采样年龄和有效性分别检查。HTTP bridge 的新鲜度门限不能覆盖设备自己的失效判断；BLE 设备返回 `E:STALE` 时保留过期状态。空气湿度、空气 ADC、UV ADC 分别使用原有含义，不能换算为土壤含水量、CO₂ 或 PAR。

## 4. Skill 对话与联通检查

先按 [Skill 教程](honor-platform.md) 安装对应版本。最小对话版只声明 `skill_exit`；下载的0.2.1包还支持显式请求的无效凭据联通诊断。

| 操作 | 预期结果 |
| --- | --- |
| “今天好累，陪我一下” | 简短自然回应，不自动触发设备动作。 |
| 在未接入读数时询问湿度 | 说明暂无实时数据，不使用示例值。 |
| 对话版请求浇水或打印 | 说明未执行，不调用未声明的能力。 |
| “开始番茄钟”“换主题” | 指向 Indicator 本地操作。 |
| “退出盆栽伙伴” | 调用 `skill_exit`，返回 YOYO。 |
| 重新进入技能 | 不重放之前的动作请求。 |
| 0.2.1中请求“测试蓝牙联通” | 发送一次固定 `S|probe|soil`，收到 `E:AUTH`；这是鉴权拒绝，不是土壤读数。 |

查看可用的工具调试轨迹，核对目标设备、参数和业务回包。正式读取与控制需要独立配置设备凭据。

## 5. 外设与异常处理检查

只有安全凭据注入、完整长写和通知回包已经确认，并且 Skill 版本及门禁经过显式修订后，才进入这一阶段。真实水泵最后测试，先用电平观察或合适的测试负载；详见 [BLE 联调](ble-integration.md) 和 [排障](troubleshooting.md)。

### 只读与错误传播

| 编号 | 测试条件 | 预期行为 |
| --- | --- | --- |
| D01 | 全部执行器禁用，查询土壤/环境 | 完整请求到达正确设备；对应通知被手机收到；未知和未标定值保持原样 |
| D02 | 错误令牌 | 设备明确拒绝；没有动作；日志不显示真实令牌 |
| D03 | 选错设备或找不到设备 | 不转而控制另一台；工具错误和设备身份清楚 |
| D04 | 数据过期或 `valid=false` | 不报告为“当前正常”；不由此自动浇水 |
| D05 | 无 NOTIFY、畸形/截断回包、ID 不匹配 | 结果未知或明确错误；不把 GATT 写确认当动作完成 |
| D06 | 断连后出现旧连接回包 | 不将旧数据或旧请求结果套到新连接/新动作 |

[官方 BLE 参数](https://developer.honor.com/cn/doc/guides/101781) 区分 `ack_type=ack` 的写确认与 `expect_response=true` 的业务响应等待；成功码说明和 Schema 的 `0/200` 差异仍需实机记录。完整请求需要实测 MTU/长写：最短 16 字符令牌下 UV 查询 21 字节、土壤查询 23 字节，不能默认放进常见 20 字节 ATT 载荷。

### 单项动作、断网和重复请求

每个新动作生成新 ID；查询保留原 ID。HTTP ID 长度与 BLE 短 ID 约束不同，按 [设备协议](../device-protocol.md) 和 [BLE 契约](../../integrations/yoyo/skill-draft/references/ble-contract.md) 分别执行。测试中有意重发只用于受控台架验证去重，不能成为正常客户端超时重试策略。

| 编号 | 测试条件 | 通过条件 |
| --- | --- | --- |
| D07 | 明确开灯，再明确关灯 | 只有灯动作；匹配请求结果；实物亮灭分别确认 |
| D07a | 逐项选择 solid/breath/chase/rainbow，再在动态效果中关灯 | HTTP effect 匹配；单灯 chase 按约定呼吸；关灯无需等完整周期，实测延迟记录 |
| D07b | 同 ID 重试默认/solid，随后换模式；关灯带 effect | 默认/solid 不重启；换模式冲突；off+effect 拒绝；复位后默认关灯 |
| D08 | ASCII 打印一次 | 受理与 UART 发送完成分开记录；实物出纸人工确认；超时不补打 |
| D09 | 同 ID、同参数的重复包 | 设备只执行一次；重复响应可指向原结果 |
| D10 | 同 ID、不同参数 | 冲突明确拒绝，不执行替换后的动作 |
| D11 | POST/写操作送出后断网或响应丢失 | 客户端报告 unknown；只按原 ID 查结果，不换 ID 再发 |
| D12 | 结果查询未命中、设备刚重启 | 保留“不确定”；不把记录缺失当成“肯定没执行” |
| D13 | 缓存达到上限 | 新普通动作拒绝；已知记录保留；停止策略按本地实现验证 |
| D14 | 请求超过允许时长 | 拒绝或明确说明限制；不拆成多次脉冲绕过 |

### 水泵、停止与中途退出

| 编号 | 测试条件 | 通过条件 |
| --- | --- | --- |
| D15 | 外设禁用时请求浇水 | 不起泵，明确拒绝 |
| D16 | 允许的短脉冲 | 实际起止、电平/负载、设定时长、请求 ID 对应；停止由 XIAO 本地完成 |
| D17 | 起泵后手机断连、网络断开 | 即使没有下一条网络消息也在本地时限内停止 |
| D18 | 起泵后用户退出 Skill/关闭应用 | 不取消设备自己的截止时间；重新进入不重放动作，按原 ID 查询或现场检查 |
| D19 | 传感器无效/过期时明确要求停泵 | 停止不等待传感器分析；记录真实动作结果与实物停机 |
| D20 | 停泵命令响应丢失 | 不能口头保证已停；保留未知、使用现场停止，不反复发新 ID 赌网络 |
| D21 | 重启、掉电再上电 | 泵默认关闭，不恢复旧动作；重新读取设备状态 |
| D22 | Indicator 与手机同时操作 | 结果关联到各自 ID；没有另一入口覆盖后误报当前动作的情况 |

首次台架可按硬件教程将本地最大泵时长降至 1000 ms、用 500 ms 请求测试；Indicator 默认请求时长也必须同步降到不超过当前上限。软件 `completed` 仍不等于测得水量；没有流量标定时不报告毫升。

网络停止不是物理急停。测试者必须在现场能切断泵支路，不能为了复现网络异常取消硬件保护。某一项失败就保存日志并回到相应层排查，不用更换 ID 或重启反复尝试来掩盖未知结果。

## 6. 界面与扩展检查

### 虚拟照料和真实控制

由不熟悉项目的人分别执行“给屏幕小植物浇水”和“给真实花盆浇水”。观察对方能否在点击前说出哪一个会启动真实泵。若分不清，即使技术通信正常也应判体验失败，优先修改入口、文案和反馈。浏览器演示、本地养成奖励和真实设备动作分别标注；屏幕计时完成不证明手机能后台提醒。

### 用户自带硬件

[设备平台](device-platform.md) 的当前验收是三套 profile 可被离线验证、未知数据保持未知、登记后不能偷偷换 profile、`hardware_id` 与设备数据匹配，以及没有网络调用和执行入口。

通用 BLE 模板通过不等于任意蓝牙设备可用；灌溉 planned profile 通过不等于现场控制器可部署。新适配器要重做实际报文、身份、断线、联锁与单设备验收。多用户、多设备选择、绑定/解绑和远程调度需要单独测试，当前没有完成这些能力。

### 云端辅助查询

使用云端查询时，先检查服务、本地网关和设备连接。健康检查仅表示进程存活；真实网关缺席时状态应为 `unavailable`，结果可能为 `unknown`，四个动作工具包括停止均应拒绝且 `sent=false`。云查询与手机 BLE 分别检查。

## 7. 反馈问题

记录最小复现步骤、固件与手机版本、首条异常日志及相关请求ID，再按 [排障手册](troubleshooting.md#如何提交一份可复现的问题记录) 整理问题。设备令牌和完整 Flash 备份留在本地。
