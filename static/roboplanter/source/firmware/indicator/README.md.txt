# RoboPlanter — original SenseCAP Indicator client

Current bench (2026-10-29): Indicator D1 joins the same2.4GHz router as XIAO and uses authenticated HTTP. RP2040 GPIO27 relays soil; environment now comes from SEN54, Light v1.2 and Ultrasonic v2.0. The focus timer is shared with XIAO. Its passive RP2040 GPIO19 buzzer has an opt-in persisted switch; listening test remains pending. See [current wiring](../../docs/wiring.md) and [YOYO guide](../../docs/handbook/yoyo-companion.md). Pairing-code UI improvements are compiled but not reflashed.

This project runs on the **original 4-inch, 480×480 SenseCAP Indicator D1's ESP32-S3** with OPI PSRAM. It provides an offline plant companion, a shared XIAO focus timer and local settings, plus a Wi-Fi HTTP client for XIAO readings and manual commands. The network client preserves missing and stale data rather than inventing readings. D1 has no built-in CO₂/VOC sensor and requires an external sensor for temperature/humidity. The optional `PLANTER_ENABLE_LOCAL_SOIL` path reads the internal RP2040 soil responder; it is disabled by default and does not replace or reset RP2040 firmware. Do not connect an additional UART/GPIO cable between Indicator and XIAO.

## Optional local soil relay

The original Indicator's left Grove yellow wire is RP2040 GPIO27. With `PLANTER_ENABLE_LOCAL_SOIL=1`, a separate task uses ESP32 RX20/TX19 and RP2040 TX16/RX17 at 115200 baud. Install the opt-in [MicroPython responder](../indicator-rp2040-diagnostics/soil_uart.py) on the already backed-up RP2040 and explicitly run `import soil_uart; soil_uart.serve()` from its `main.py`. Preserve any existing `main.py` before replacing it. The stock COBS firmware is not compatible with this diagnostic protocol.

Requests carry a random challenge; responses must echo it, pass CRC16-CCITT and contain ADC12 values in 0–4095. A response timeout is 250 ms. Accepted samples expire after 1500 ms locally. The HTTP worker forwards fresh samples to XIAO's authenticated `/api/v1/sensors/soil`; no HTTP work runs in the display/touch task. Uncalibrated readings appear with an `ADC` unit and calibration hint, never as a moisture percentage. The relay does not perform automatic watering.

For shared-LAN testing, configure both boards for the same actual 2.4GHz network and set `PLANTER_BASE_URL` to the XIAO's observed LAN address. Saved Indicator Wi-Fi settings take priority over compiled defaults; use its Wi-Fi settings if it selects an old network. Broker credentials are not part of this local relay, and this firmware does not yet implement native MQTT.

## Build and configuration

1. Copy `include/local_config.example.h` to `include/local_config.h` (ignored by Git).
2. Set the actual shared-router SSID (or optional XIAO SoftAP), password, XIAO origin and matching device token. Defaults are `RoboPlanter-XXXX`, `planter-demo`, `http://192.168.4.1`, `change-me-before-use`. The placeholder SSID is intentionally not automatically discovered. The default token is for setup only; change both boards together.
3. Build from this directory with `pio run -e sensecap_indicator`. Building does not upload firmware.

Pinned toolchain: PlatformIO `espressif32@6.12.0` / Arduino ESP32 2.0.17, GFX Library for Arduino **1.4.7**, ArduinoJson 6.21.5. The environment selects 8 MB flash and octal PSRAM. Seeed's current Arduino tutorial uses core 3.1.2 / GFX 1.5.3. That library version does not compile against this core's IDF 4.4 RGB/SPI structures, so this project pins 1.4.7: its [official RGB driver](https://github.com/moononournation/Arduino_GFX/blob/v1.4.7/src/databus/Arduino_ESP32RGBPanel.cpp) explicitly targets Arduino core versions below 3. The display pin map, ST7701 type1 table and application API remain the same. A successful compile does not establish that a particular physical screen batch works.

The 2026-10-24 baseline empty-album build is the **v3 plant companion with VSYNC double buffering and thin settings icon**, built and uploaded on 2026-10-24. Static RAM is 47,776 / 327,680 bytes; application flash is 1,324,493 / 3,342,336 bytes. The application image `.pio/build/sensecap_indicator/firmware.bin` is 1,324,864 bytes, SHA-256 `140C335CC9F0CCE892537564580A3D6809F2B2DD02B18FED490C8122E304C504`. Runtime allocations, including two 480×480×2-byte PSRAM framebuffers and the HTTP task stack, are additional to static RAM. Build/upload/startup logs are `tmp/indicator-thin-gear-{build,flash,boot}-20261024.log`; see [the latest icon record](../../docs/deployment/indicator-icons.md), [double-buffer validation](../../docs/deployment/indicator-vsync-double-buffer.md) and [first-flash/backup recovery](../../docs/deployment/indicator-first-flash.md). The optional photo path was compiled earlier with one generated test image; the recorded current build retains the empty album.

**First ESP32 upload completed on 2026-10-24**, through the CH340 port identified as COM13 for that session. A verified 8 MB pre-upload backup was saved locally. After intermittent flicker in the initial garden revision, the VSYNC double-buffer build passed 96 frame swaps and storage readbacks; the user then reported no further flicker during the short observation and normal touch. The subsequent thin-icon build retained that renderer, passed upload verification and a 20-second startup observation, restored the saved plant/language/brightness, and reported no panic. Its new icon appearance awaits user feedback; long-running stability and the full game/network workflow are not established by the short check. The RP2040 port (COM14 in that session) and XIAO were not flashed. Identify ports again before any later upload or restore.

## Desktop companion UI

The UI uses charcoal backgrounds, ivory cards, sage, soft purple and aqua accents. The home page now contains a growing pixel plant spirit: mint, basil, rose or succulent, each progressing from seed through sprout, leaves, bloom and maturity. Eight palettes share the navigation and game rules: 工位花园、紫色午后、薄荷微风、暖光书桌、夜航工位、莓果便签、苔绿书房、像素街机. The earlier CRT-planter artwork is historical; current native captures are linked from [the preview guide](../../docs/previews/README.md).

The Chinese/English five-page flow is plant spirit → today → information → photos → focus timer. Tap the plant body to enter today, swipe left/right to navigate, and use the top button to choose a palette. Theme choice persists in Preferences. The settings gear opens saved language, 2.4 GHz Wi-Fi scan/password entry, 5–100% backlight and device information. The current font contains **516 characters independently rasterized at 16, 24, 32, 48 and 64 px** from Noto Sans SC under OFL; larger text does not upscale the 16 px glyphs. See [font source/license and regeneration](assets/fonts/README.md). The subset does not cover arbitrary Chinese SSIDs or photo titles.

Each plant has its own local saved progress; only the selected plant accumulates online time, and switching off pauses all plants. Growth requires both time and earned growth points. Virtual watering, feeding, weeding and companionship have need checks and cooldowns; life has a floor and no permanent death. The user explicitly chooses the shared desk atmosphere; this is not emotion detection. **Virtual care never sends pump or other actuator commands and game values are not sensor measurements.** Explicit changes are coalesced for about two seconds, online progress is checkpointed every 60 seconds, and failed storage is visible. A sudden power loss can discard unsaved progress. See [the complete garden rules](../../docs/indicator-garden.md).

The timer supports 25/5/15 minutes, start/pause/resume/reset, and continues through navigation, theme and language changes. Running or paused sessions must be reset before changing duration. Completion waits for a manual restart. Completing 25 minutes of focus awards the selected plant once; short/long breaks, pause/reset and repeated display of the completed screen do not award it. There is no sound, phone notification, or YOYO timer/theme/garden API. Power cycling clears the unfinished timer while successfully saved plant progress remains. Photos are optional local RGB565 assets, packed before building; the default screen shows an empty album. See [the UI and photo guide](../../docs/indicator-ui.md).

Touch is interpreted only on a real release; a tap requires both its start and end inside the target. I²C errors, multiple contacts, and out-of-range coordinates cancel the gesture until a real release. Settings and garden overlays consume their own gestures. A swipe, theme or settings change never emits an actuator request. Hardware buttons live in a separate panel opened from Today. Water and print open a confirmation view; the final tap rechecks current device availability before submitting. STOP has no extra confirmation step. The current top bar has a wide double-arc Wi-Fi icon and thin-outline settings gear; the settings hit area remains 44×44 px. The icon shows Indicator Wi-Fi status, not proof of a live planter connection. The plant body remains fixed while blinking, stars and celebration particles animate; none imply valid sensor readings or real plant health. Animated views use a 100 ms update interval (at most about 10 fps); ordinary static refresh is 1 second, with input events repainting immediately. Actual frame rate also depends on drawing and frame handoff time.

The renderer uses **two complete RGB565 framebuffers and a VSYNC-synchronised swap**, not a full-frame copy into active scanout. `IndicatorCanvas` borrows the driver's back buffer, draws a complete frame, writes back the cache and publishes it; the VSYNC ISR switches the DMA chain before releasing the old front buffer. The two buffers together use 921,600 bytes of PSRAM. If handoff exceeds 100 ms, no buffer is returned for writing and rendering stops, preserving the last frame instead of drawing into memory with uncertain ownership. The narrow RGB driver is pinned to Arduino 2.0.17 / ESP-IDF 4.4.7 with its interrupt path in IRAM/ROM. This removes the concurrent front-buffer rewrite but does not eliminate every possible Flash/PSRAM contention issue; see [the design and measurement limits](../../docs/deployment/indicator-vsync-double-buffer.md).

Recorded host verification includes 99 portable UI-model checks; four garden model/storage scenarios with 421, 412, 421 and 412 assertions (including repeated common assertions); and native rendering checks covering 40 production-handler interactions, 44 growth examples, 84 fixed-position/blink checks and 6 failed-frame-handoff checks. The thin-icon revision repeated the native rendering checks; its changed pixels were confined to the icon region. Native PNG/GIF previews directly run production drawing code with the pinned Arduino_GFX rasterizer, including current garden stages, palettes, settings and confirmation views. Font checks cover all five native sizes and the current text subset. These checks do not simulate LCD timing, DMA/PSRAM behaviour, touch hardware or physical animation speed. See [latest recorded results](../../docs/deployment/indicator-icons.md), [double-buffer evidence](../../docs/deployment/indicator-vsync-double-buffer.md), [settings checks](../../docs/deployment/indicator-settings-ui.md) and [reproducible preview commands](../../docs/indicator-ui.md).

## Hardware assumptions and official sources

Pin definitions come from Seeed's [Arduino tutorial](https://wiki.seeedstudio.com/SenseCAP_Indicator_ESP32_Arduino/) and [official board source](https://github.com/Seeed-Solution/SenseCAP_Indicator_ESP32/blob/77edb8d2b9a92fc67965c1b2d4a838f0d09a1800/components/bsp/src/boards/sensecap_indicator_board.c). Display configuration is ST7701, 12 MHz, 480×480, matching the full Arduino example linked by that tutorial. The tutorial's introductory generic `Arduino_SWSPI` sketch is insufficient for expander CS; this project explicitly routes CS through PCA9535 P04.

| Signal | ESP32 pin / expander bit |
| --- | --- |
| RGB DE / VSYNC / HSYNC / PCLK | 18 / 17 / 16 / 21 |
| R0…R4 | 4, 3, 2, 1, 0 |
| G0…G5 | 10, 9, 8, 7, 6, 5 |
| B0…B4 | 15, 14, 13, 12, 11 |
| Backlight | 45 |
| ST7701 software SPI SCK / MOSI | 41 / 48 |
| Internal I²C SDA / SCL | 39 / 40, 400 kHz |
| PCA9535 address / LCD CS / LCD reset | 0x20 / P04 / P05 |
| Touch interrupt / touch reset | P06 / P07 |
| FT5x06 touch address | **0x48** |
| Reserved internal UART, unused here | ESP32 RX20 / TX19 |

RGB timings are H polarity 1/front 10/pulse 8/back 50, V polarity 1/front 10/pulse 8/back 20. Arduino_GFX's `st7701_type1_init_operations` provides the panel register sequence; the two orientation settings C7=04 and 36=10 match Seeed's [linked full Arduino example](https://github.com/LongDirtyAnimAlf/SenseCap/blob/8003fb320db707f051d8b7d14d5be4d95e0e870c/SHT31Demo/ESP32/src/Display/Indicator_RGB_Display.h). Touch mapping is `(479−rawX, 479−rawY)`, matching that example's [rotation-0 touch code](https://github.com/LongDirtyAnimAlf/SenseCap/blob/8003fb320db707f051d8b7d14d5be4d95e0e870c/SHT31Demo/ESP32/touch.h).

**Original-board LCD batches still matter.** The official BSP calls the ST7701/0x48 screen configuration `CONFIG_SENSECAP_INDICATOR_SCREEN_GX`; its other screen configuration uses 0x38. Those are LCD configuration names in the original Indicator SDK, not proof of a new whole-device model. See the [official FT5x06 driver](https://github.com/Seeed-Solution/SenseCAP_Indicator_ESP32/blob/77edb8d2b9a92fc67965c1b2d4a838f0d09a1800/components/i2c_devices/touch_panel/ft5x06.c) and [panel initialisation](https://github.com/Seeed-Solution/SenseCAP_Indicator_ESP32/blob/77edb8d2b9a92fc67965c1b2d4a838f0d09a1800/components/bsp/src/boards/lcd_panel_config.c). This firmware fixes 0x48 explicitly; it does not scan and guess. If touch is absent, the UI/serial log report it. Confirm the actual screen batch before changing addresses or register tables.

The minimal expander driver reads/modifies **only port 0** output/configuration bytes. Other port-0 bits are preserved; port 1, including RP2040 reset, is untouched. FT5x06 touch settings and register addresses follow the official driver. Arduino_GFX remains an external dependency with its upstream licence. `src/indicator_rgb_driver.cpp` adapts the narrow LCD initialization and DMA/VSYNC restart path from ESP-IDF 4.4.7 under Apache-2.0; attribution is in the source and the license is in `third_party/esp-idf-LICENSE`.

## Network and command behaviour

The HTTP worker is a FreeRTOS task on core 0; drawing and touch remain in the Arduino loop. No HTTP request runs inside touch handling. Wi-Fi reconnects without replaying actuator commands. HTTP connect/read timeouts are 1500 ms each, redirect following is disabled, and bodies are bounded (state 4096 bytes, command/result reply 2048 bytes). The XIAO endpoints must return Content-Length; chunked/unknown-length replies are rejected. State polling is approximately once per second, after previous network work completes.

- `GET /api/v1/state`, header `X-Device-Token`, requires `schema_version: 1`. The state fields follow `docs`' shared XIAO API. Sensor values missing, invalid or uncalibrated are shown as `--`, never fabricated zero. Air/UV are explicitly raw ADC readings, not gas concentration or UV index.
- A reading is stale when XIAO's `sample_age_ms` plus time since receiving it exceeds 5 seconds, or its age is absent. Offline/stale readings are labelled and dimmed. Unknown capabilities are unavailable. Water/light/print require fresh state and `enabled: true`.
- `POST /api/v1/command` carries `request_id` and an action: `water` with a configured 2000 ms pulse, `stop_water`, `light` with `on`, or `print` with a frozen check-in note matching the preview. Chinese UI uses Chinese when the device advertises `printer.text_format="utf8-raster"`; English UI and older firmware use English. The UI reports the configured autocutter without claiming a physical cut. Request IDs contain an ESP32 random boot nonce and monotonic sequence, within the 32-character limit.
- Only one ordinary command is outstanding. Touch repeats are debounced. STOP has a separate priority queue, cancels any unsent ordinary command, and remains available with stale data when Wi-Fi is connected and the pump was reported enabled. It cannot interrupt an HTTP operation already waiting for a timeout. This is a network stop button; the XIAO must independently enforce pump duration and output safety.
- `queued`, `sending`, `accepted`/`running`, `completed`, and failure are distinct. A 2xx response alone is not completion. State polls reconcile a matching `last_command.request_id`. While a transmitted command remains unresolved (including `accepted` or `unknown`), each polling cycle also calls authenticated `GET /api/v1/result?request_id=<id>` after the state poll. This reads the XIAO's result cache even if another controller's command has replaced `last_command`. A returned ID must match, and responses for a superseded request cannot overwrite a new STOP or an acknowledgement.
- **Water/print are never automatically retried**, including a lost response. Only the read-only result lookup is repeated. An ambiguous response or missing final result becomes `unknown`, blocks ordinary actions, and asks the operator to inspect the planter. A result `404` with `request_not_found` also remains unknown: cache eviction or a device restart can erase a command that already executed. The explicit inspection acknowledgement button unlocks ordinary actions without resending; STOP remains available. The screen does not invent completion when no matching result is available.

The connection is local HTTP protected by the XIAO's Wi-Fi and matching token, not TLS. The token is not printed in logs or displayed on screen. It is not intended as a public Internet endpoint.

## Pairing and diagnostics

When the device advertises `printer.layout="receipt32-v2"`, the print preview uses the same 32px font, line wrapping and raster bands as the printer, fitted to the screen with its aspect ratio preserved. The first line is centered and separated from the body; the paper uses 44-dot line spacing. A queued preview cannot silently downgrade to another layout. The larger maximum receipt has a 100-second result window, including slow 9600-baud transmission and device scheduling margin. Screen pixels do not represent physical millimeters.

Run `python tools/pair_indicator.py --url http://<current-XIAO-IP> --device-id <device_id>` from the repository root to generate the ignored `include/local_config.h` from the existing private XIAO configuration, after one authenticated read-only identity check. Use `--replace` to update existing pairing fields while retaining other local options, then rebuild and upload. The Settings → Planter connection page shows the configured origin, paired network and HTTP/error status, never the token. It can restore the paired Wi-Fi; it does not change the trusted origin or credential. Print recovery requires inspection and restart of both the printer and controller, not repeated commands.
