# 先验收资产，再接入主页

## 视觉与模块检查

整体对照 `source_art/` 内已经确认的平屋顶、窄街角、红黑紫霓虹车库，不回退到原来的大紫色双坡屋顶。车库外壳保留开放门洞，内部左工具区、右作品展示区分别设置；正面招牌、门片、招财猫和项目贩卖机都是可独立替换的资产。

生成的外壳参考中仍有电箱、灯与植物。如果 Tripo 将这些融合进建筑网格，需要在 Blender 清理或把重复独立道具移除；不能叠加两套外墙装饰。

## 下列要求是 Blender / Three.js 阶段的目标，不是已生成特性

| 项目 | 验收内容 |
|---|---|
| 朝向与比例 | Y 向上、正面 +Z、地面中心原点，按 manifest 的目标尺寸人工校正 |
| 屋顶 | 分离 `ROOF_MAIN`，需要时可单独隐藏或淡出 |
| 卷帘门 | 连续涂鸦 UV；单独门片、卷轴和开关，不用整张静态门面缩放冒充卷起 |
| 招财猫 | 右爪有独立部件和肩部转轴；初稿静态 GLB 不等于自动有招手动画 |
| 头像招牌 | 只保留圆框、中心贴图面与独立发光材质；使用用户核对过的真实照片 |
| 贩卖机 | 有可定位的展示格、玻璃、按钮和取物口；屏幕显示真实项目，不承诺购物功能 |
| 作品展示区 | 空槽容纳 PAN、FlipFate、BMO、Roomba 等用户真实项目模型；不虚构替代作品 |
| 工具区 | 工具名称与实际工具清单核对；不要将概念图中的通用仪器当作用户拥有的型号 |
| 文字 | 清除生成乱码、错误猫头 Logo 与假指标；中文路牌、英文涂鸦以单独贴图制作 |
| 灯光 | 发光材质与金属分离；Three.js 做受控 Bloom，低动态模式停用装饰闪烁 |
| 地面 | 湿区有可调整粗糙度；绘制在颜色图上的高光不能代替真实反射 |
| 浏览器 | 桌面/手机构图、触屏和键盘导航、视角限制、帧率和加载失败回退实测 |

## 一次性整合，而不是边做边把官网改乱

在独立开发分支组装并截取桌面和手机效果；确认视觉接近已认可的设计后，才替换 Docusaurus 首页。文件下载成功、构建成功、模型存在、视觉通过和已上线，是五个不同状态，必须分别记录。

本包没有将任何文件标为“已通过视觉验收”，没有生产 GLB、部署脚本或自动改写博客配置的代码。
